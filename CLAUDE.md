# Zombie Survival — Strasbourg

Co-op zombie survival game (solo or up to 4 players) on the Grande Île of Strasbourg, rebuilt from OpenStreetMap and IGN BD TOPO data.
Browser game: Three.js + Vite, Node.js WebSocket relay. Deployed on Render from `main`. Game text is in French.

## Technical memory
- `docs/ARCHITECTURE.md` is the long-term reference (rendering pipeline, perf mechanisms, building/interior generation, determinism, scaling limits). Read the relevant section before engine or city work; update it in the same change when you alter one of those systems.
- Library docs pinned to our versions: branch `reference-docs` (three.js r170, Vite 6, ws 8, Playwright, MDN Web Audio/WebGL); read with `git show origin/reference-docs:<path>`.
- Performance budgets: ≤ 300 draw calls and ≤ 1.5 M triangles per view, `game.update` p95 ≤ 4 ms, heap ≤ 400 MB, ≤ 60 shader programs. Measure before and after with the `perf-check` skill (v0.87.1 island start: 858 calls, 2.29 M triangles, 756 MB).

2. Play the scenario in the real game with Playwright and `?debug` (see the `play-test` skill). Look at the screenshots you take.

## Architecture (src/)
- `main.js`: the `game` object (rounds, points, zombies, doors, machines, power-ups, host/client networking, game loop) and the renderer/scene setup. Systems are `installX(game, ctx)` modules that attach methods to `game`. `window.game` is exposed.
- `config.js`: every tunable value (weapons, Pack-a-Punch levels, zones and their items, perks, vehicles, finale, graphics, terrain, day/night).
- World: `realworld.js` (builds the city from `public/data/area.json`: buildings, doors, zones, machines, nav grid, collision), `architecture.js` + `relief.js` (facades and their 3D relief: window trims, bands, plinths, quoins), `ground.js` (ground shader), `terrain.js` (height map: the vertex shader displaces all static scenery; logic uses `terrainY` / `world.floorAt`), `cathedral.js` + `cath/` (cathedral), `tram*.js`, `hommedefer.js`, `trees.js`, `props.js`, `island.js` (water / island mask), `levels.js` (floors, stairs, `floorAt`), `collision.js` (2D segments/circles with height bands), `nav.js` (flow field), `interiors.js` (walkable ground floors: rooms, doors, shelves; rooms are hollowed in the nav grid only at the final build). Single map: Strasbourg (the vehicle test circuit and the test arena were removed in v0.78.1).
- Station: `gare/` is the Gare de Strasbourg, a separate playable area at its real coordinates (`public/data/gare.json`, `rail.json`): `plan.js` (pure geometry from the real outlines, local frame u along the tracks / v toward the forecourt), `build.js` (meshes), `index.js` (floor region with its own nav grid, zones `pocket: 'gare'`, doors, items, spawns, map; `world.areaOf` / `setLocalArea` draw only the local player's area). `transfer.js`: tram Gare Centrale ↔ Homme de Fer (host decides: `xf_req`, `xf_call`, `xf_go`; ride, fade, teleport). `?debug&gare` starts at the station.
- Actors: `player.js` (movement, weapons, perks hooks), `zombie.js`, `boss.js`, `angel.js`, `tanner.js`, `finale.js` + `summit.js` (endgame, dawn sky, day/night cycle), `perkFx.js` (the 9 extra perks), `remote.js` (teammates).
- Vehicles: `vehicles.js` (driving physics, HP, fuel, wrecks, network), `vehicleCrash.js` (car body collisions with impulses, dents, broken glass), `vehicleModels.js` (models), `rideCam.js`, `bikeStation.js`, `parking.js`.
- Weapons: `viewmodels.js` (builder: B box, C/Y cylinders, P extruded side profile, L lathe; Pack-a-Punch accessories via anchors), `weaponParts.js` (the part lists of the 23 weapons), `weaponDisplay.js` (wall weapons).
- Rendering & UI: `graphics.js` (quality levels, post), `sky.js`, `fx.js` (particles, decals), `envmap.js`, `hud.js`, `ui.js`, `modMenu.js` (F9), `debugMenu.js`, `scoreboard.js`, `keybinds.js` / `keysMenu.js`, `audio.js` / `music.js`, `chat.js`.
- Server: `server/rooms.mjs` (WebSocket relay, host-authoritative game), `server/prod.mjs` (production server).
- Tools: `tools/fetch-rail.mjs` (SNCF / OSM / IGN data of the station and the tracks), `tools/stuck-scan.mjs` (map defects, `AREA=gare` for the station), `tools/mp-smoke.mjs` (3-tab multiplayer smoke test), `tools/make-docs.mjs` (docs), `tools/weapon-sheet.html` (weapon contact sheet), `tools/ship.mjs` (one-command release, `tools/scopes.json` per-agent file scopes), `tools/audio-smoke.js` (calls every sound, run via the harness), `tools/fetch-osm.mjs` (map data).

## Multiplayer model
The host simulates (zombies, AI, bosses, vehicle HP, power-ups); `server/rooms.mjs` only relays. Clients send requests (`z_hit`, `v_dmg`…), the host answers with state. Each driver simulates their own vehicle and broadcasts `v_state`. Purely local: particles, HUD, view interpolation, day/night sky.

## Three.js rendering directives (dark realistic survival look)
- Renderer: `ACESFilmicToneMapping`, `SRGBColorSpace`, `PCFSoftShadowMap`, pixel ratio capped at 2.
- Lighting: no white or strong ambient. Dim cold `HemisphereLight`, faint bluish moonlight `DirectionalLight` with shadows; local `PointLight`s (blue Quick Revive, warm amber lamps and windows) with `decay: 2`. Dark `FogExp2`.
- Materials: `MeshStandardMaterial` / `MeshPhysicalMaterial` only for world meshes; desaturated gritty colours, roughness 0.6–0.9, subtle metalness; glowing elements use `emissive` for the bloom pass.
- Geometry: no bare sharp boxes ("Roblox look"): add chamfers, frames, rims, profiles. Ground needs normal / roughness / puddle variation.

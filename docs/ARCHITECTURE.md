# Architecture — technical memory of the project

Long-term reference for anyone (human or agent) changing the engine, the city generation or the performance. Facts below were read from the code at **v0.87.1** (2026-11-12), with `file:line` pointers; re-check a pointer before relying on it, lines move. Balance values are in `src/config.js`, generated tables in `docs/REFERENCE.md`. Official library docs, pinned to the versions used: branch `reference-docs` (see its README).

## 1. Stack and code conventions
- Three.js **r170**, Vite **6**, `ws` **8.22** relay. ES modules, no framework, no bundler plugins. Entry `src/main.js` (top-level `await buildRealWorld`, `main.js:106`).
- **Module pattern**: `installX(game, ctx)` attaches methods/state to the `game` object; `ctx` is the subset of `{ world, scene, hud, sfx, fx, camera, … }` it needs. About 20 installers, called in `main.js` (around lines 1710-1726 and 2240). New systems follow this pattern.
- **Config**: every tunable in `src/config.js` (`CONFIG.x.y`), never a literal in logic (known exception: the round zombie count `(4 + 3r)` in `main.js` ~1051).
- **Language**: game text French; code, new comments, docs, commits English (old code has French comments: keep them). Versions tagged in comments `(v0.NN.N)` where behaviour changed.
- **Networking**: JSON `{ t, … }` over WebSocket `/mp`; the relay adds `from`, routes optional `to`, 4 players. `net.on(type, fn)` / `net.onHost(type, fn)` (host-only senders). Host-authoritative: clients send `*_req` / `z_hit`, the host answers with state. Message families: `z_*` zombies, `v_*` vehicles, `t_*` tram, `tn_*` train intro, `xf_*` transfer, `box_*`, `pap_*`, `pu_*`, `finale_*`, `dbg_*` (host only).
- **Determinism**: map generation uses Mulberry32 `rnd` seeded `20240611` (`realworld.js:179`) plus `rndOuter` 77002, `rndIso` 77001, `rndExtra` 77003. Removed/ghost buildings still consume `rnd` so the sequence stays aligned (`architecture.js:707-721`). Relief and interiors use position hashes. Visual-only `Math.random`: rubble, window cracks, interior floor dirt. Every client builds the same city from the same data: never add `Math.random` to anything that affects collision, nav, zones or doors.

## 2. Rendering pipeline
- **Renderer** (`main.js:49-54`): antialias, `high-performance`, sRGB output, tone mapping re-applied by `graphics.js:116-124` from `CONFIG.graphics.tone` (ACES 1.05 × brightness × zone exposure). `renderer.info.autoReset = false` (`graphics.js:296`).
- **Scene**: background `0x04060c`, `FogExp2(0x050810, 0.021)`, camera far **170 m**. Lights: `HemisphereLight` 0.28 + one shadow-casting `DirectionalLight` "moon" 0.42 following the player (snapped), shadow camera ±45 m.
- **Light rule**: never add/remove/hide a light at runtime (every shader would recompile). Local lights = a **pool of 8 `PointLight`s** reassigned every 0.4 s to the nearest entries of `world.lightSources` (`realworld.js:2240-2261`); new lamps register a light *source*, never a light. Plus the player's torch, muzzle flash, explosion light, vehicle headlights.
- **Quality levels** (`CONFIG.graphics`, `applyQuality` in `graphics.js:199-218`; default 1 "Normale"):

| Level | pixel ratio | shadows | shadow map | shadow every | facade relief range | trees | post |
|---|---|---|---|---|---|---|---|
| 0 Rapide | 0.75 | off | 1024 | 2 frames | 30 m | balls | no |
| 1 Normale | 1 | PCF | 1024 | 2 frames | 60 m | cards | no |
| 2 Haute | device ≤ 2 | PCFSoft | 2048 | every frame | 110 m | cards + branches | yes |

  `shadowMap.autoUpdate = false`; the loop sets `needsUpdate` every `shadowEvery` frames (`main.js` ~2705).
- **Post (Haute only)**, custom, no EffectComposer (`graphics.js:162-185, 304-317`): 4× MSAA HalfFloat target (`isXRRenderTarget` trick so materials tone-map before writing), final quad = sRGB + 32³ LUT grade + halo (threshold at half resolution, 4 separable gaussian passes). Skipped above 4.3 Mpx, 2× MSAA above 2.4 Mpx. Vignette and grain are CSS (`#cinema`).
- **Environment**: 512×256 canvas sky → PMREM → `scene.environment` (target reused), rebuilt when sky `k` moves > 0.06 (`graphics.js:127-159`, `envmap.js`).
- **Sky / day-night**: `sky.js` dome (`ShaderMaterial`, renderOrder 1000, no fog); cycle in `summit.js:146-168` (14 real minutes per day; `k` 0 night, 0.5 dawn, 1 day); `applySky` drives background, fog, hemi, moon, interior daylight, lamp scale. `holdNight(hour)` freezes it (intro).
- **Frame loop** (`main.js` ~2691-2708): `game.update(dt ≤ 0.05)` → HUD, clock, scoreboard, chat, music mood → shadow flag → `gfx.update` (exposure, sky, trees, contact shadows) → `gfx.render()`. Inside `game.update`: vehicles, transfer, intro, ride zombies, train, player, `world.setLocalArea(world.areaOf(player))`, summit, perks, remotes, `world.update` (LOD), moon, levels, nav flow field, grenades, box/PaP, rounds, zombies, power-ups.
- **Areas**: `areaOf(x, z)` → `'gare'` (station rectangle and the intro corridor) or `'island'`; `setLocalArea` toggles `visible` on the island roots vs `gare.root` (local only, no-op when unchanged).
- **Shader patches**: terrain displacement (`terrain.js:84-114`, half-float height texture, 2 m cells, static scenery only; dynamic bodies use `terrainY`), facade texture array + detail texture + per-vertex layer and depth bias (`facadeAtlas.js`), interior daylight dimming (`interiors.js:283-290`), ground SDF of facade footprints at 1 m (`ground.js`). Every `onBeforeCompile` patch must set `customProgramCacheKey`.
- **Shader precompile** (`main.js` ~2548-2589): temporary zombies/boss/avatars, hidden objects shown, `frustumCulled` off, `gfx.compile()` + one render, so the first fight does not stutter. Objects with `userData.lod` stay hidden.

## 3. Performance mechanisms (and budgets)
- **Budgets** (targets, see the `perf-check` skill): ≤ 300 draw calls and ≤ 1.5 M triangles per view at default quality, `game.update` p95 ≤ 4 ms, heap ≤ 400 MB, ≤ 60 shader programs, 60 FPS on a mid-range PC.
- **Measured v0.87.1, island start** (`tools/perf-probe.js`): 858 draw calls, 2.29 M triangles, 11 343 meshes, 5 863 geometries, 373 textures, 85 programs, 756 MB heap.
- **Measured after the draw-call pass (step A1), same view, day (fog 0.011)**: **271 draw calls** (breakdown: 224 main + 40 shadow), 1.97 M triangles (1.56 M main + 0.40 M shadow), 8 178 meshes (2 352 visible), 3 054 geometries, 320 textures, 85 programs, heap 756-803 MB (noisy, unchanged), update 0.6 ms median / 3.3 ms p95. Station quai 1: 319 -> 185 calls; intro: 110 -> 96. Triangles were still over 1.5 M: fixed by step A2 (below).
- **Measured after the triangle and heap pass (steps A2 + A3), same view**: **279 draw calls** (233 main + 40 shadow), **1.10 M triangles** (0.92 M main + 0.18 M shadow), heap **347-368 MB** measured after a forced GC (the harness launches Chromium with `--expose-gc` and `tools/perf-probe.js` calls `gc()`; before: 803 MB, of which 575 MB were typed-array backing stores), 85 programs (unchanged, see below), update 0.4-0.6 ms median (p95 is noise-bound on a shared machine: 1.3-8 ms on both the old and the new build). Station quai 1: 185 calls, 0.64 M triangles; intro: 96 calls, 0.51 M triangles.
- **Triangle mechanisms added in A2**: **ground chunks** (`groundChunks.js`, `CONFIG.graphics.groundChunk` 120 m): the tessellated ground plane (450 k triangles, 1.35 M non-indexed vertices) was ONE mesh drawn in full every frame; it is now split into indexed chunks with their own bounding sphere (~10 visible = 28 k triangles, +10 calls); **tree culling** (`trees.js`, `CONFIG.graphics.trees.range` 185 m / `rebuild` 12 m): each instanced layer keeps its full data on the CPU and the visible buffers are rebuilt with the trees within range of the camera whenever it moved 12 m (before: every tree of the map, 230 k triangles in the main pass and again in the shadow pass; now ~3 k + 1 k). Remaining big main-pass items: props `bin` (110 k, 900 triangles per instance), relief quoins (108 k), sandbags (57 k).
- **Heap mechanisms added in A3**: **GPU-only geometry** (`gpuOnly.js`): static city meshes (facade tiles, roofs, interiors, relief statics, shadow proxies, station, rails, ground chunks, apron, gates) compute their bounding volumes, then free each CPU vertex array right after the GPU upload (`attribute.onUpload`); `warmUpload` (called by `precompileShaders`) renders the hidden LOD meshes once with a 1-pixel scissor so interiors (198 MB) are uploaded and freed at load, not when first approached. Never use it on geometry that is edited, cloned, merged or raycast later (vehicles, tram doors, zombies); a lost WebGL context reloads the page (the CPU copies are gone). The architecture builder also frees its per-material build buffers at the end of `finish` (they were ~90 MB of JS arrays kept alive by a closure). What is left (347 MB): ~74 MB attributes (instance matrices, viewmodels, cathedral, train), nav grids 3 x 12.5 MB (`dist`, `distB`, `labels`) and ~20 MB of zone masks held by build closures, ~30 MB JS arrays (collision grid), 26 MB of dev-server source strings.
- **Shader programs (85 -> 58, target 60, reached; step A4)**: the 85 were all distinct parameter combinations (no duplicate cache keys), but many differed only by a flag three.js bakes into the program. Merged without visible change: (1) **terrain code on every standard / basic material** (`terrain.js`): `THREE.Material.prototype.onBeforeCompile` injects the same terrain vertex chunk into every MeshStandard / MeshBasic material, switched per material by the `uTerrainK` uniform (1 = patched scenery via `patchMaterial`, 0 = dynamic bodies and `noTerrain` meshes), so a patched material and its unpatched twin share one program (-14; the shared uniforms `tTerrain` / `uTerrain` live in one object, the patched set is a WeakSet so clones do not inherit it); materials with their own `onBeforeCompile` (foliage, facade, ground, interiors, zombie skin) keep their own key plus `|terrain`; (2) **`programShare.js`**: a map-less MeshStandard / MeshBasic material (no normal / roughness / emissive... map either) gets a shared 1x1 white map, so it shares the program of its textured twin (also merges the shadow depth variants, because three copies `material.map` onto the depth material); a transparent DoubleSide material is drawn in one pass (`forceSinglePass`) instead of BackSide + FrontSide, which compiled FLIP_SIDED + plain programs for every kind (-7); applied to the whole scene before `precompileShaders` compiles, and lazily by `Material.prototype.onBeforeRender` for materials created later (it runs before the program lookup); (3) the shadow proxy material is a MeshStandardMaterial so `renderer.compile` (which also walks hidden meshes) reuses the scenery program instead of compiling a MeshBasic one (-1). Rules to keep it at 58: do not give a material its own `onBeforeCompile` without a shared `customProgramCacheKey`; avoid new flat-shaded, vertex-colour, Physical or normal-map variants of materials that already exist without them; re-count with `game.renderer.info.programs.length` after the precompile at the island, `debug&gare` and `debug&intro` (the whole world is built and precompiled at load, so the count is the same everywhere). Remaining: 2 PMREM, ~10 custom shaders (facade, foliage, ground, interiors, zombie skin, sky, sprites, points), 7 shadow depth variants (instancing x instance colour x map x side), ~39 scenery / prop combinations.
- **Draw-call mechanisms added in A1** (`CONFIG.graphics`): **shadow proxies** (`shadowProxy.js`: one merged position-only caster per city tile, switched on only while the shadow map renders by wrapping `renderer.shadowMap.render`; the facade meshes themselves do not cast; 75 -> 6 calls) plus `castShadow` only on the big parts (machine body, first part of `propShadows` types, characters; no gates, wall boards, interiors); **build-time merging** (`bake.js` `bakeGroup` merges a group's meshes per material, `boxMaterialGroups` sorts box faces into one group per material): perk machine 16 -> 4 meshes, ammo station 9 -> 5, wall board 6 -> 2, mystery box, Pack-a-Punch, clock, weapon viewmodels 20 -> 5 per weapon (hands, magazine, optic, stock, bolt stay separate); the parts that differ only in paint share one material through vertex colours (`tint`); wall boards share one 2x1-texel lamp material; **gate batching** (`gateBatch.js`: every paid-door barricade is baked in world space and merged per material per 320 m chunk, price signs share one texture atlas; buying a door rebuilds the chunks it touched); **detail culling** (`detailCull.js`, `CONFIG.graphics.detailCull`: city tiles, gate chunks, machines, stations and wall boards are hidden beyond `fog / FogExp2 density` m (2.0: 1.8 % visibility, so 94 m at night, the 170 m camera far by day), checked every frame for the frustum test of tight tile boxes; wall lamps beyond 45 m; island area only); **`CONFIG.graphics.cityTile`** 160 -> 240 m: each tile costs ~20 calls (one per facade material), so fewer tiles in view beat the extra off-screen triangles (83 -> 40 facade calls at the island start). Remaining main-pass calls at the island start: facades ~40, relief ~33 (windows, cornices, plinths, quoins per tile), props ~34 (instanced, `frustumCulled = false`), interiors 16, perks/boxes ~25, wall boards ~20, gates ~8, characters ~15. Done in C1: the ~20 facade materials per tile are one texture-array material with a per-vertex layer and depth bias. What would cut more: BatchedMesh per material for the props, and static merging of cornices/plinths into the relief tile.
- **Measured after step C (C1 + C2), same view**: **245-254 draw calls** (was 279; the spread is the relief static meshes that fall in or out of range), 1.13 M triangles (was 1.10 M: dormers, soffits, mansards, oriels, static pieces), JS heap + external buffers **362 MB** (was 365; measured with `--enable-precise-memory-info`, 2 forced GCs: `performance.memory` is bucketed and jumps between 290 and 1000 MB without that flag, so compare only precise readings), 85 programs (unchanged: the facades were already one program, the array only removes the ~20 per-tile meshes). Facade walls are now ONE mesh per 240 m tile (`arch:walls`) plus one roof mesh (`arch:roof`); `aFac = (layer, depth step)` per vertex replaces the per-material `polygonOffset` and the per-tile material clones (`tileMat`). Pitfall met: closures created in `facadeAtlas.build` shared a scope with the 100 MB pixel arrays and kept them alive after the upload (+116 MB of ArrayBuffers in a heap snapshot): null them explicitly.
- **InstancedMesh**: relief (windows, balconies, cornices, plinths, quoins: `relief.js:163`), props (`props.js:328`), trees, manholes, particles/decals, contact shadows, interior lamps, tram network, train, ride scenery, station.
- **Merged geometry**: buildings = one merged wall mesh and one roof mesh **per tile** (`architecture.js` `finish`, tile size `CONFIG.graphics.cityTile`, 240 m), depth steps in `aFac.y`: walls 2 tile parities, roofs 4 (z-fighting). `mergeGeometries` also in relief, characters, train, rail, station.
- **Distance LOD / culling** (checked every 0.25 s unless noted): relief tiles 32 m (windows) / 64 m (rest) within the quality range; interiors 64 m tiles within 70 m; station items 60 m; ride scenery 300 m chunks within 190 m; rail chunks 200 m; zombies not drawn/animated beyond 170 m; contact shadows 45 m.
- **Known costs** (from the code, not profiled): props and `instanced()` meshes have `frustumCulled = false` (drawn in every direction), every tile is built up front (no streaming), several full-grid nav/zone passes at load, ~19 facade canvas sets drawn at start, `assignLights` sorts all light sources every 0.4 s, `CONFIG.gare.lightsMax` is unused.

## 4. City generation (Grande Île)
- **Data**: `public/data/area.json` (1.4 MB) from `tools/fetch-osm.mjs` (OSM + IGN BD TOPO heights `ignH`). Frame: origin `center` lat/lon, **x east, z south, metres**; half extent 820 × 560 m. Content: 3 186 buildings (2 970 with `ignH`), 764 building parts, 62 passages, 61 water polygons, 2 127 trees, 159 lamps, ~1 950 furniture items, rails, platforms (`roads`, `parks`, `barriers` are empty). Loaded once with the station data (`realworld.js:178-191`), rings repaired by `stitchRings`.
- **Building → mesh** (`realworld.js:470-521`, `architecture.js:684-772`):
  1. Buildings with `building:part`s (cathedral, churches) are drawn from the parts.
  2. Storeys from `building:levels`, else `round((h − 4.2) / 3.25) + 1` (ground floor 4.2 m, upper floors 3.25 m, bays 4 m), capped 1–8 by `ignH`.
  3. Style (step C): `archStyle.js` `classify()` (pure, seeded from the building centroid, not the world `rnd`): gothic, civic, classical (18th c. hôtels), modern, timber, plaster, neustadt, chosen by tags, then by the weighted mix of the district (`CONFIG.architecture.districts`: Petite France, cathedral, Broglie, Grande Percée, island, off-island N / rest), with downgrades (timber needs area ≤ 320 m², ≤ 5 levels, frontage ≤ 12 m). `node tools/arch-stats.mjs` prints the count per style per district. Each style has its own storey height, bay width, roof pitch, dormers and facade layers (`CONFIG.architecture`); the ground floor stays 4.2 m. Shop front on the ground floor when commercial (or 38 % near the start), 4 new French signs (KOUGELHOPF, CHARCUTERIE, TAVERNE, HORLOGERIE).
  **`rnd` replay**: `legacyDraws()` in `architecture.js` consumes the world `rnd` in exactly the old order (old style, variant, shop, lazy legacy textures, offset, tint, dirt, roof colour, 2 draws per dormer candidate of the OLD roof), so machines, items, perks and the box do not move (check: `window.__rndAfterBuildings` under `?debug` and a hash of the item positions). The old canvases are still drawn lazily with the world `rnd` (the texture content is unused unless a legacy layer is picked: gothic, shops); every new layer uses a local `prng`. Never draw the world `rnd` anywhere else in `building()`.
  4. Walls = quads per wall slice with vertex tint and a foot ambient-occlusion ramp; passages cut openings.
  5. Roof: flat, pyramidal/dome/onion/cone, skillion, mansard ring, gabled (+ dormers, chimneys); hipped variants become gabled or mansard by half-width ≤ 9.5 m.
  6. Relief (`relief.js`, instanced): window trims (`WIN` table), balconies, cornices, floor bands, quoins, plinths, pipes, chimneys.
  7. Facade textures (`facadeAtlas.js`, `facadeLayers.js`, `facadeDraw.js`): every layer is a canvas set (map 768×640, bump ½ as R8, emissive ¼) copied at `finish()` into three `DataArrayTexture`s (only the layers used by the built geometry get a slice: 14 at the island start), canvases and CPU arrays freed. One `MeshStandardMaterial` patched in the shader (`customProgramCacheKey 'facadeArray'`, chained after the terrain patch): the vertex attribute `aFac` (Uint8 pair) gives the slice (flat varying) and a depth step (`gl_Position.z -= step * CONFIG.architecture.depthBias * w`, ~1 LSB of a 24-bit buffer per step, same units as the old polygonOffset; +1 for odd tiles so neighbouring tiles never share a depth). The cathedral floodlight is a per-layer weight (`uFlood`). The roof material uses the same depth step (`patchDepth`). Texture arrays ignore `flipY`: the rows are flipped when copied. 19 legacy layers + 24 new ones, ~3.4 MB of GPU memory each.
  8. Step C1 geometry: timber houses overhang 0.22 m per storey (max 3) on street walls with soffits and return faces (street = open ground outside, `streetEdges` from `realworld.js`), steep 55-60° roofs with shed-dormer rows (1-4), Petite France top storeys open into slatted lofts (40 %), gable triangles with their own layer; plaster 3.1 m storeys, 45-52° roofs, 0-2 dormer rows; classical hôtels with 3.5 m storeys, 70° mansard (slate) with one dormer per bay and a painted carriage door (70 % when the street wall has no cut); civic 4.2 m arcades; neustadt 3.6 m rusticated blocks (oriels, turrets, stepped gables and static relief come in C2). Dormers are built by `dormer()` (6-9 triangles, capped by `dormers.maxPerRoof`).
  9. Step C2: neustadt oriels (3-sided prisms, 2.6 × 0.8 m, floors 1-3, one per 12 m on street walls ≥ 14 m, the relief window frames behind them are skipped) and corner turrets (10-sided, corbelled, cone roof; 40 % of the convex 60-120° street corners of buildings with ≥ 4 levels, max 2) are base geometry; civic gabled roofs get stepped Renaissance gables (35 %). Static relief (`relief.box` / `relief.ribbon`, merged per 64 m tile into `relief:static`, so no draw call of their own, hidden beyond the facade relief range): oak corbels under timber overhangs, barge boards along timber gable edges, shop pilasters and cornices, carriage-door jambs and keystone. Not done: dormer frames and slat pieces as relief (dormer fronts are painted), Heimatstil rough render, per-layer roughness.
- **Zones and doors** (`realworld.js:802-1373`): zones flood-filled on the nav grid from seeds in `CONFIG.sector` (origin zones capped at 95 m); a door wherever two reachable zones touch (one per pair); price = max of the two zones' `doorPrice`. Items (`'station'`, `'wall:<id>'`, `'perk:<id>'`, `'box'`) placed by `spotIn` (`realworld.js:1480`), ≥ 5 m apart.
- **Collision** (`collision.js`): 2D segments (height band `y0`/`h`, kind wall/prop) and circles (vaultable ≤ 1.15 m) in a 4 m hash grid (`ix*4096+iz`); `setDynamic` boxes outside the grid; extra playable rectangles via `bounds` (station).
- **Navigation** (`nav.js`): grid 0.75 m (≈ 2 187 × 1 493 cells for the island), `Uint8Array blocked` (2 = vaultable), double-buffered `Int32Array` flow field, bounded per call (range 160 m, 25 000 cells, every 0.2 s, `maxCost` 1300). Built 2–3 times at load (before/after interiors, after sealing).
- **Interiors** (`interiors.js`, `realworld.js:449-469, 2124-2175`): a building gets a ground-floor room if height ≥ 4 m, area 25–3 000 m², the 0.22 m inset is valid and an edge faces open street (`chooseDoor`). Door cut 2.4 × 3.6 m; parquet or tile floor (subdivided ≤ 2.5 m for the terrain shader), wainscot, shelves (50 %), one ceiling lamp (light source + instanced fixture); 64 m tiles, 4 buckets (walls, two floors, furniture). Rooms are hollowed in the nav grid only at the final build; a room whose door is blocked, invaded by a prop or unreachable is **sealed** with a closed door. Each room takes the zone of its street.
- **Key buildings** (`keyBuildings.js`, `CONFIG.keyBuildings`; step D): "Immeuble fortifié", 1-2 per zone (30 on the island), picked before the facade loop of `realworld.js` (deterministic: no `rnd`; candidate = ordinary building with a street door, 2+ storeys, no `height` tag, inset area 100-700 m², oriented-box width >= 8.5 / length >= 15 m, fill >= 0.7, within `pickRadius` of the zone seed; best area fit + hash, `minSpacing` 40 m). Layout in the frame of the minimum-area box: a dog-leg stair shaft (2 lanes of 1.1 m + 0.2 m divider, flights of 4.2 m, landing 1.2 m, access strip 1.2 m) in the end farthest from the street door, a corridor of the shaft's width running away from it, partitions every 4-6.5 m (ray-clipped to the inset outline, one doorway per room onto the corridor), the last room (5 m deep, doorway on the corridor axis) is the future last stand room. Floors k = 1..`upper` (`min(storeys-1, 2)`) are at `4.2 + 3.25 (k-1)`; each is a `Levels` floor region (with the shaft as a hole, own nav grid 0.4 m / margin 0.35) joined by one `stair` region + link per storey (path = both flights and the landing; region 0 is the ground room: its stair foot is in the room). Collision: shaft walls at every height, a cross wall under flight B (`h = 4.2`), a closed alcove on lane A of the top floor, partitions with height bands (`y0 = y_k - 0.2`, `h = y_k + 3`: the street nav ignores them through its `segFilter`), a segment closing the street-door gap above head height. `interiors.js` gives the ground room a ceiling hole above the shaft (`room.ceilHoles`) and exports its materials (`interiors.mats`) so the upper floors reuse them (no new shader program): one merged mesh per material per building (<= 4 calls), visible only while the camera is inside the footprint (+1 m); lamps are light sources with `off` until then (`assignLights` sorts by 3D distance). The ground nav grid blocks the shaft interior (`nav.finalize` hook: otherwise the flow field targets the walled-in lane). After the navs are built `validate()` drops a building whose room got sealed, whose floor nav is split (< 80 % connected) or without stair route (link `closed`, meshes hidden). A key building belongs to the zone of its street door (`room.zone`), which can differ from the zone whose seed picked it. `facadeSegs` skips key buildings (no zombie window spawn inside); `world.ceilingAt(x, z, y)` knows the stacked ceilings; `relocateZombies` maps players on upper floors to their stair foot. Test helper: `game.tpKeyBuilding(i, floor)`, `world.keyBuildings`, `world.kbAt(x, z)`.
- **Window barricades** (`barricades.js`, `CONFIG.barricades`; step D): each key building has 2-3 ground-floor windows (`pickWindows` in `keyBuildings.js`: street-facing facade spots >= 3 m from the door, passages and each other, not behind the shaft). They are cut in the facade with `[t0, t1, sill, lintel]` cuts (`architecture.js` draws the sill and lintel pieces, `interiors.js` the inner wall pieces, reveals and a wooden sill; `addRoom` keeps the extra numbers when it flips the winding); the facade collision skips them, `keyBuildings.js` adds a `h = Infinity` board segment at the facade line plus a disabled vault box (h = sill). While planks remain: board on, nav cells of the opening = 3 (`nav.barCost` 60 in the flow field, still blocked for `isBlockedAt` / `los` / `components`); at 0 planks: board off, vault box on, cells 2 (sill) / 0, so zombies (`_tryVault`) and players (Space) climb in; a repair from 0 closes it again. `nav.finalize` re-stamps the cells at every nav build; a demoted key building gets permanent boards (`perm`). Zombies (host / solo only) call `world.barApi.tear(z, dt)` before moving: within `tear.reach` and heading for a boarded window they stop and tear a plank per `base - perRound * round` s (>= `min`), at most `maxPerBarricade` per window (4 m hash lookup every 0.2 s per zombie). Players hold the interact key (prompt chain in `main.js`, text « Maintenir : réparer la barricade (+10) ») for `repair.time` s per plank (Speed Cola halves it): +10 points, 500 per round and player (client counts its own cap). Network: `bar_fix {id}` client -> host (checked against the sender's position), `bar {s: [id, n, by, k, ...]}` host -> all every `sync` s (k planks added by `by`, who adds their own points), `bars` in the join `sync`. Presentation: one `InstancedMesh` for frames and one for planks (hidden plank = zero-scale matrix, terrain-patched material), debris meshes are local. `game.repairBarricade(id)`, `world.barricades`, `world.barApi` for tests.
- **Chokepoints and fallback points** (step D, chunk 3): the **stair door** is a normal `doors[]` entry (`interior: true`, `a === b === the building's street zone`, `link`, `hit` points for `nearDoor`, price `max(500, round250(0.5 x zone doorPrice))`, mesh in `kb.meshes`) closing lane A at ground level; while closed its link is `closed` (`Levels._buildHops` skips it: zombies ignore players upstairs and do not climb; `validate()` checks the route as if the door were bought) and `world.openDoor` only opens the stair (no zone, no 750 price clamp: `applySpawnPoint` skips `interior` doors). The top floor's last room (`kb.lastStand`, 5 m deep, one doorway on the corridor axis) holds a `door` barricade (6 planks, same entity as the windows: board segment on the top floor height band, floor-nav cells 3 while boarded, `afterNavs()` stamps them; torn = open) and an **ammo crate** (`kb.crate`, collision box; `game.nearCrate()` / `crateLeft`: refills the reserve of the weapon in hand once per round per player, local state, no message). Walking into the room shows « Point de repli : tenez la position ! » (`barricades.js`, once per round and building). The **deployable barricade** ("Barricade de fortune", `deploy` keybind, foot context): near an ammo station the key buys it (750 pts, one kit), elsewhere it places it `deploy.place` m ahead; the host validates (`placeCheck`: sequential id, floor region with a nav grid, <= maxTotal on the map and maxPerPlayer per owner, nav cells and collision free along the central 1 m, >= clearDoor from any door point, >= clearItem from stations / machines / wall weapons) and answers `bar_new {id, x, z, yaw, region, owner, n}` to everybody (or `bar_no {why}` to the sender, `bar_place` is the request); it is a 4-plank barricade (collision segment `h = 1.5`, cells 3 so the flow field stays connected) that is removed when torn; the join `sync` carries `bars: {n: [[id, n]], d: [deployed]}`. **Explosive barrels** (`barrels.js`, `CONFIG.barrels`): 2 per key building next to the windows (placed after the world is final: collision circle inserted in the grid, nav cells blocked), two instanced meshes; `game.shootBarrels(ro, rd, wallT)` is called by `player.js` for every pellet (a barrel is solid for `rayHit`, so the bullet ends on it), a hit explodes it through `game.explode` (zombies, local player damage), chains within `radius` after `chainDelay`; `brl_hit {id}` client -> host, `brl_boom {id, o}` host -> all, `brls` (dead ids) in the join snapshot, back at every round (`startRound` / `round_start`).
- **Station** (`src/gare/`): separate area at real coordinates (x −1260…−800, z −620…−60), own nav grid; `plan.js` is pure geometry in a local frame (u along the tracks, v toward the forecourt; `plan.W(u, v)` → world), `build.js` meshes, `index.js` zones/doors/items/spawns. Data `public/data/gare.json`, `rail.json` (`tools/fetch-rail.mjs`: SNCF tracks, OSM outlines, IGN heights).
- **World tiles (step B, chunk 1)** (`rng.js`, `tiles.js`, `tools/tiles.mjs`, `CONFIG.world`): the island core (`area.json`, rect ±820 × ±560 m) is frozen: built by `buildRealWorld` exactly as before, same `rnd` order (digest: FNV over stations, wall weapons, machines, boxes, door cells, `startPos` in cm + `__rndAfterBuildings`, identical before and after), never streamed. Everything outside comes from **480 m tiles** (`public/data/tiles/t_<ix>_<iz>.json`, tile (ix, iz) covers `[ix * 480, (ix + 1) * 480)` in the frame of `area.json`) listed in `manifest.json` (`tileSize`, origin, core, per tile `{k, file, bytes, sha, counts}`, global `hash`). `node tools/tiles.mjs --fetch x0,z0,x1,z1` downloads one raw OSM `map.json` per tile (+30 m halo) from api.openstreetmap.org (Overpass mirrors kumi.systems / private.coffee as fallback; run with `NODE_USE_ENV_PROXY=1` behind the proxy) into the git-ignored `.cache/tiles-raw/`; `--build` writes the tile files (building belongs to the tile of its centroid, a way with ANY vertex in the core rect is dropped because `area.json` already holds it, halo outlines are flagged `halo` and never built, sorted by OSM id, cm precision: the manifest hash is byte-stable); `--verify` checks the hashes. IGN heights are not reachable from the build box: `h` comes from the OSM `height` tag, then `building:levels`, then `CONFIG.world.defaultLevels` (`hSrc` records which). Shipped: the 4 Esplanade-side tiles `(1,-1) (1,0) (2,-1) (2,0)` (x 480..1440, z -480..480; 514 buildings, 1 057 trees, 71 lamps). Since v0.96 each tile also carries the flat map layers `roads` (OSM highways: `hw` class, `bridge`, `area` for pedestrian squares, `um` for unmarked crossings; footway=sidewalk / crossing are their own classes; tunnels dropped), `water` (closed water ways + stitched outer rings of water multipolygons), `rivers` (waterway lines the polygons do not cover) and `parks` (leisure / landuse / natural green areas): a feature is kept when its bbox touches the tile + halo and is not entirely inside the core rect, the readers dedupe by id (the buildings / trees / lamps arrays are byte-identical to before).
  - **Determinism**: `rng.js` owns `seeded` (Mulberry32, moved from `realworld.js`, same output) and `hash32` / `tileSeed(ix, iz, stream)` / `tileRng` / `districtRng(id, stream)` (integer maths only, no `Math.sin`: portable). A tile building seeds its draws from the hash of ITS OWN POSITION (`hash32(round(cx*10), round(cz*10), seed ^ streams.facade)`), a tile tree's height from the hash of its position: nothing depends on the build order, so a tile rebuilt after an unload is identical (checked: per-tile digest = vertices, triangles, position sum, trees, lamps). A new system takes a new id in `CONFIG.world.streams`.
  - **Streamed architecture**: `createArchitecture({ ..., stream: coreArch.streamKit() })` makes a second instance that draws no canvas and creates no material: walls use the core's texture array and wall material, roofs the core roof material, `relief` is `nullRelief` (painted windows only, like the station's background), a layer the core atlas does not hold maps to `CONFIG.world.layerFallback`, then to the same style family, then to `plasterP:0`. `building(..., { rnd })` swaps the world generator for the tile's. `flushTile(ix, iz)` turns the buildings built since the last flush into ONE wall mesh, ONE roof mesh and the proxy triangles (depth parity by tile like the core split), and empties the builders: a tile is built in one go, one tile at a time.
  - **Flat map layers** (`src/surfaces.js`, `CONFIG.world.surf`): `buildSurfaces(tileData)` merges every road, pavement, crossing, park and water body of a tile into TWO geometries: `tile:surf` (asphalt strips, pavement strips and pedestrian squares, grass polygons, the stone coping around water, dashed centre lines on roads >= 7 m, zebra stripes on marked crossings; one material = vertex colours x one 128 px grain texture, planar UV, so ONE new shader program) and `tile:water` (the island's own water material, shared through `world.stream.water`, so no new program; ripple UV in metres). Strips are mitred, split every 6 m for a smooth wear variation (`wear()` is a pure function of position: overlapping coplanar strips differ by < 2 %, no visible z-fight); layers sit 8 mm apart (`surf.y`: park, asphalt, pavement, markings, water, quay coping, bridge deck) with `polygonOffset` on the material. Features whose centroid / segment lies in the core rect are skipped (the island draws its own). 2 draw calls per built tile; visual only, walking on them needs nothing (open ground is already walkable).
  - **Streamer** (`tiles.js`, `game.tiles`, local and visual only: no network message): states absent -> data (JSON) -> built (GPU) -> data -> absent, residency checked every `stream.checkEvery` s around the local camera with hysteresis (build when the tile's edge is within `visIn` 300 m, dispose beyond `visOut` 380 m, drop the JSON beyond `dataOut` 900 m, at most `maxBuilt` 6 built, a nearer tile evicts the farthest one). The build is a generator run `sliceMs` per frame; every pass over a big array is itself stepped (`flushTileSteps` yields per 16 k vertices and per attribute, `buildSurfacesSteps` every 8 features and before each geometry), so a step is one building (<= ~5 ms) or less: worst step measured 5.6 ms (was 8.8 ms surfaces / 7.8 ms flush, and 28-77 ms outliers on a loaded machine); the tile digest is unchanged (`game.tiles.focus` runs with no time limit, so its `maxStepMs` is the whole building loop: measure steps by calling `game.tiles.work(0)` in a loop). A built tile owns: wall + roof meshes (`gpuOnly`, `detailCull` boxes), the merged shadow proxy, ONE ground mesh (the tile minus the island ground plane, shared ground material, same UV mapping so the pavement continues; the ground shader already clamps its facade-distance map to "far" outside its bounds), TWO flat-layer meshes from `surfaces.js` (below), its trees (`trees.addSet(key, list)`: CPU slots in the island layers, `CONFIG.world.treeCap` 1 200 extra slots, 0 draw calls) and its lamps (2 instanced meshes with the island lamp materials, so no new program, plus light SOURCES, never lights). Once a build is done, `warmTiles` sends the tile's meshes and its shadow proxy to the GPU at once (`warmUpload(scene, renderer, render, meshes)`, one 1-pixel-scissor render per batch of builds): a tile beyond the detailCull range is hidden and a proxy is only seen by the shadow camera when the tile is near, so without it each built tile kept ~1.2 MB of CPU vertex arrays (district heap 393.3 -> 388.7 MB, measured precise, island start 386.8, back on the island 387.9). `dispose(t)` frees all of it: geometries, instance buffers, detailCull entries, proxy, light sources, tree slots; shared materials, the facade array and the lamp geometries are never disposed. Test helpers: `game.tiles.focus(x, z)` (pretend the camera is there, resolves when idle), `.stats()`, `.digest(key)`, `.check()`, `.work(ms)`; `?notiles` disables the streamer. Tiles are render-only by themselves; the walkable part (collision, nav, zones) comes from the districts (Krutenau, below).
- **Krutenau district (step B chunk 2)** (`src/district/index.js`, `bridge.js`, `CONFIG.districts.krutenau`, 4 zones `pocket: 'krutenau'` appended after the station's): the east tiles become a walkable AREA, built like the station but from tile data.   - **Gate and bridge**: ONE door (`gate: true`, `a === b === first district zone`, price `gatePrice` 3 000, `extra` = the other three zones) stands on the island's east edge (`island.find` in `realworld.js`: reachable street cell nearest to `gateHint`, gate across the street axis; no nav cell, no collision segment: the gate is a sign + barricade mesh and the island nav is untouched). `world.openDoor` opens `d.extra` zones too. ## 6. Limits for scaling to the whole city
- One monolithic `buildRealWorld` (~2 340 lines) and one data file; every tile built at load, only `visible` toggled.
- Island-sized full grids: nav at 0.75 m would be ~10× larger for the city; `Int8Array` zone labels cap zones at 127; hash keys `*4096` / `*8192` cap coordinates.
- Hand-placed coordinates: zones, start hints, spawn points, cathedral, Homme de Fer, station, finale.
- Step B (chunk 1) lifted the render side: tiles stream around the camera (see §4 "World tiles"); nav, collision and zones of the core are unchanged; the first district (Krutenau, §4) has its own area. The ~20 MB of build-time zone masks (`zoneLabel`, `zoneLabel1`, the breach start mask) are detached with `ArrayBuffer.transfer` at the end of the build; the runtime keeps `zoneLabelWide`, `zoneLabelWide1` and `reach`.
- Plan to lift them: data split into tiles (one JSON per ~500 m tile, generated by the fetch tool), deterministic per-tile generation (seed = hash(tile)), per-tile nav and collision with portals between tiles, load/unload around the players, pooled GPU buffers, zones defined per district in data rather than in config.

# Gameplay Coder

## Purpose
Implement gameplay mechanics cleanly, separating simulation logic from rendering and strictly adhering to configuration files.

## Guidelines
- Separate state update logic (delta-time based) from visual rendering.
- All balance values must reside in `src/config.js` (or `godot/data/config.json`), never hardcoded.
- Verify changes after every modification.

### Browser (`main`)
- Modern ES modules, no global variables.
- Systems are organized as `installX(game, ctx)` modules attached to `game` in `src/main.js`.
- Verification: run `npx vite build`, then test live scenarios with `?debug` and Playwright scripts in `tools/`.

### Godot Port (`godot-port`)
- Typed GDScript for Godot 4.7.
- Pure simulation logic in `godot/sim/` (RefCounted, no scene nodes, custom collision logic checked against JS golden files).
- Simulation runs in `_physics_process(delta)` at 60 Hz.
- Balance is synchronized from `godot/data/config.json` (generated by `node tools/export-config.mjs` from `src/config.js`). Never edit manually.
- Verification: `tools/godot-check.sh [suite]` (must pass with 0 failures) plus visual check (`xvfb-run godot --path godot ...`).
- Commit subjects end with `(godot vX.Y.Z)`. Do not touch `package.json`.
